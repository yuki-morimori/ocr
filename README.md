# 汎用 帳票読み取りエンジン（業種切替デモ）

手書き伝票の写真を入れると、**選んだ業種の文脈**でClaudeが読み取り、
**構造化データ（JSON）＋帳票イメージ**を返すデモです。

> 売り文句は「手書きをやめて専用書式に」ではなく
> **「手書きはそのまま、写真を撮ると専用書式で出てくる」**。

特定業種専用ツールではなく、**業種をまたいで使える汎用エンジン**。
業種を増やす／変えるときは **`industries/*.json` を差し替えるだけ**で、
コア（このリポジトリの `engine/`）は一切触りません。

現在の同梱設定: **産業廃棄物処理業（sanpai）** / **運送業（unso）**。

---

## 三層構造

| 層 | 役割 | 実体 | 変わるか |
|----|------|------|----------|
| **コア** | 画像 → Claude API → JSON構造化 → 帳票生成 | `engine/core.py`, `engine/forms.py` | 変えない（全業種共通） |
| **業種別プロンプト設定** | 文脈宣言＋用語辞書＋出力の型＋補完抑制ルール | `industries/*.json` | 差し替えるだけ |
| **業種別の見せ方** | 帳票テンプレ（設定の `form` が吸収） | `industries/*.json` の `form` | 業種特化の顔で出す |

`engine/core.py` は業種に依存しません。プロンプトは設定JSONから**動的に**組み立てます。

### 業種設定（プロンプト設定）に必ず入る4要素
1. **文脈宣言** … `context_declaration`（例「これは産業廃棄物処理の計量伝票です」）
2. **用語辞書** … `glossary`（混合廃棄物／正味重量／風袋／傭車／実車 など業界語と読みの癖）
3. **出力の型** … `header_fields` ＋ `line_items`（後段の帳票に繋ぐため**項目順を固定**したJSON）
4. **補完抑制ルール（最重要）** … `suppression_rules`（無い項目は空、読めない箇所は推測せず不明）
   - 手書きの金額・重量を勝手に補完すると **請求ミス → 信用失墜** に直結するため保守的に。

## 段階エスカレーション（汚い手書きの自動救済）

通常はもっとも安い **Haiku** で読み、各項目に自信度(high/medium/low)を返させます。
`low` が含まれる、または重要項目（★金額・重量・距離）が空の伝票だけ、自動で上位モデルへ。

```
Haiku 4.5 → Sonnet 4.6 → Opus 4.8 → 「要人間確認」フラグ
```

- 終点は Opus ではなく **人間の目視**。Opus は人に回す前の最後の自動救済にすぎません。
- 汚い数字を上位モデルに**無理やり推測させて請求書に載せるのは厳禁**。補完抑制ルール
  （無い項目は空 / 読めない箇所は推測せず low）とセットで効かせています。
- 大多数の伝票は Haiku のまま → 追加コストは誤差レベル。

| 用途 | モデル | API単価(入/出 per 1M) | 1枚あたり概算 |
|------|--------|----------------------|---------------|
| 通常（大多数） | Haiku 4.5 (`claude-haiku-4-5`) | $1 / $5 | 約 **0.75円** |
| 重要数値の再確認 | Sonnet 4.6 (`claude-sonnet-4-6`) | $3 / $15 | 約 **2.25円** |
| 最後の自動救済 | Opus 4.8 (`claude-opus-4-8`) | $5 / $25 | 約 **3.75円** |

- Haiku 4.5 は `effort` 非対応・思考なし（最安・抽出に十分）。Sonnet/Opus は適応的思考＋effort。
- 業種別プロンプト（用語辞書）は `cache_control: ephemeral` でキャッシュし入力コストを削減。
- 段位は `OCR_LADDER="haiku,sonnet"` のように環境変数で変更可（Opus を使わない運用も可能）。
- 為替は `USD_JPY`（既定150）でコスト表示を調整。

結果には自信度・`needs_human_review`（要人間確認の項目）・エスカレーション履歴
（どのモデルで確定したか／概算コスト）が付き、帳票上でも該当セルをハイライトします。

## 確認シート（人の砦）＋ 自動学習ループ

エスカレーションの終点は「要人間確認」。そこを担うのが **Excel確認シート** です。
OCR → 確認シート → 人が訂正 → 読み戻し → 帳票/請求書、というループを閉じます。
そして **読み戻すたびに賢くなる**（人手の訂正をプロンプトに自動蓄積）。

```
画像 → OCR(エスカレーション) → 確認シート(.xlsx) → 人が色つきセルだけ訂正
                                      ↓ 読み戻し
                         学習を更新（誤読の訂正＋確認済み語彙）
                                      ↓
        次回のsystemプロンプトに自動注入（＝どんどん賢くなる）／帳票・請求書へ
```

- 確認シートは **赤=要人間確認 / 黄=低自信度** のセルだけ色がつき、人はそこだけ原本を見て直す。
- シートには元のOCR値が**隠しシート**で埋め込まれ、読み戻し時に人の訂正との**差分**を学習。
- 学習は2種類を `learnings/<業種ID>.json` に蓄積し、`build_system_prompt` が自動で積む：
  - **誤読の訂正**（例「丸北健設」→「丸北建設」、回数つき）→ 再発防止
  - **確認済みの語彙**（排出事業者名・品目・取引先名 等）→ 固有名詞の認識精度UP
- コードもモデルも変えず、現場の訂正が増えるほど精度が上がる（fine-tuning不要）。
- 学習データはテナントごとにランタイム蓄積（`OCR_LEARN_DIR` で保存先変更可）。

CLI/Web どちらからも回せます：

```bash
# 複数伝票を読んで確認シートを出す
python cli.py -i sanpai 伝票1.jpg 伝票2.jpg --review 確認シート.xlsx
# 人が訂正したシートを読み戻す（=学習が更新される）
python cli.py -i sanpai --apply 確認シート.xlsx
# 蓄積した学習を確認
python cli.py -i sanpai --learned
```
Web では結果画面の「確認シート(.xlsx)を出力」「学習させる」から同じことができます。

## 使い方

```bash
pip install -r requirements.txt
cp .env.example .env        # ANTHROPIC_API_KEY を入れる（任意。無くてもモックで動く）

# Webデモ
uvicorn app:app --reload    # http://127.0.0.1:8000

# CLI
python cli.py --list
python cli.py --industry sanpai 計量伝票.jpg --form out.html
python cli.py --industry unso   運行日報.jpg
```

- **APIキーが無くても動く**：`industries/*.json` の `mock` を返すのでデモが止まりません。
- **APIキーを入れると実OCR**：その場の**初見の伝票**をレイアウト固定なしで読み取ります
  （訪問先で撮ってその場で帳票化、が最強デモ）。
- APIキーは **サーバーサイドで保持**。フロントには出しません（Vercel / Cloudflare 想定）。

## 業種を1つ増やすには（コードを書かない）

`industries/<新業種>.json` を1枚足すだけ。`engine/`・`app.py`・`cli.py` は無改変です。

必須キー: `id` / `display_name` / `context_declaration` / `header_fields` / `line_items`
（任意: `glossary` / `suppression_rules` / `form` / `mock`）。

`line_items.columns` の数値列に `"sum": true` を付けると、帳票に合計行が出ます。
横展開候補（介護記録・農業の出荷伝票・整備の点検記録・飲食の仕入伝票・問診票…）も
**同じコア＋設定の追加**で対応できます。
